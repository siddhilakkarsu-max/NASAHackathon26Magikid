# PR #66: Cloudflare Pages build: static front end that talks to the public server

**What changed**
- **`tools/build_pages.py`** builds `dist/`, a static copy of the front end (planner, game, kit) for Cloudflare
  Pages. It uses the standard library only, so Cloudflare's build machine can run it as is.
  - **Redirects server calls:** it puts `tools/pages/api_shim.js` first in every page. The pages call the server
    with root paths (`/api`, `/murray`, `/terrain`, `/cubes`, `/tiles`, `/ctxtiles`). The shim sends those to the
    server through fetch, XHR, EventSource, image `src` and links, so the front-end code is unchanged.
  - **Versions assets:** local `.js`/`.css` references get `?v=<hash>`, like `frontend_delivery.py` does.
  - **Writes metadata:** `_headers` (pages always revalidate) and `build-info.json` (server, commit, time).
  - **Server address:** `https://100-20-2-83.sslip.io` by default, or `--api` / `MARSWALK_API`.
- **`deploy/cloudflare/README.md`:** two ways to deploy, Wrangler from a computer or Cloudflare building from
  GitHub (build command `python3 tools/build_pages.py`, output `dist`).
- **`tests/test_build_pages.py`**, and `dist/` is added to `.gitignore`.

**Why**
To host the front end on Cloudflare Pages, at https://fire-computers-2026.pages.dev, while the AWS server keeps
the data, maps and AI.

**How to try it**
```bash
python3 tools/build_pages.py
wrangler pages deploy dist --project-name fire-computers-2026 --branch main
```
Then open https://fire-computers-2026.pages.dev and plan a mission. Every `/api` and map-tile request goes to
the sslip server, which allows cross-origin requests (`CORSMiddleware` in `app.py`).
