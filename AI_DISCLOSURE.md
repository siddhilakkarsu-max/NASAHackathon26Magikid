# AI use disclosure — Marswalk Planner (team MagiKid, NASA Space Apps 2026)

We used AI tools while building this project. This file says where, and what people on the team decided and
checked.

## 1. Writing code and documentation (development tool)

- **Anthropic Claude** (Claude Code / Claude chat) helped write and review much of the code, tests and
  documentation: the Python back end (`app.py`, `build_cube.py`, `mission.py`, `physics.py`, `search.py`,
  `murray.py`, the weather and radiation modules, `gear/`), the Cesium front end (`frontend/`), the survival game,
  the procedural 3D vehicle models (`build_route_models.py`, `tools/make_rover_glb.py`) and the docs.
  Commits made with it carry a `Co-Authored-By: Claude …` line, so they can be found with
  `git log --grep "Co-Authored-By: Claude"`.
- The team chose the problem, the challenge approach, the features, the data sources, the safety rules and the
  numbers used as limits (vehicle ranges, oxygen use, reserves, landing rules), reviewed the changes in pull
  requests and tested the app. Every merged pull request is listed in `docs/changelog/`.
- Assumptions that are the team's own, not NASA's, are labelled as such in the code and in the README
  ("Honest limits"): e.g. the 500 m landing standoff, the 30-minute storm-shelter target, the scout-bike figures.

## 2. Inside the running app (optional feature)

- When an `OPENROUTER_API_KEY` is set, the mission planner asks a **free large language model on OpenRouter** to
  (a) turn a typed goal into search criteria when it contains words the keyword parser doesn't know,
  (b) write a plain-language explanation of why a route won, and (c) label points along routes.
  The app shows when the AI is working ("The AI is thinking…").
- The AI never chooses the routes: scores, routes, resources and safety checks are computed by our code from the
  data. Without a key the app uses a keyword parser and a template explanation, and everything else works.

## 3. Research

- Some data sources and background papers were first found with AI chat tools (e.g. ChatGPT). Every source we
  use was opened and checked by a team member, and is cited from its original publisher (see
  `docs/SUBMISSION_REFERENCES.md`).

## 4. Data, images, video and audio

- **All map data is real mission data** (NASA, USGS, ESA/LMD and published science datasets; see
  `docs/SUBMISSION_REFERENCES.md`). No map layer, measurement or image of Mars was generated by AI.
  Some layers are physical models computed from that data (surface temperature, radiation dose, travel cost);
  the app labels them as modelled.
- The 3D vehicle and astronaut models are original geometry generated by our own code, drawn by comparison with
  NASA and ESA reference pictures; they are illustrations, not exact copies of flight hardware.
- Demo video: no AI-generated video, voice or music.
- The page design followed the team's own Figma design.
